# H0 硬件冒烟测试执行方案

## 目的与边界

本方案用于建立 GEC-ESP32-S3 V1.0.1 的实机硬件基线，不实现桌宠 UI，也不覆盖当前未知旧固件，除非后续明确确认烧录。

- 目标芯片：ESP32-S3，Flash 16 MB，PSRAM 8 MB。
- 工程：小智 AI v2.3.0，ESP-IDF v5.5.4。
- 原理图：`ESP32-S3-V1_0_1`（V1.0.1）；其网络推导见 `hardware_baseline.md`。
- 默认不写 PCA9557，不启用背光、功放或摄像头电源，不触发传感器复位脚。
- 测试按门槛逐项推进。某项连接、有效电平或控制关系不明确时，停止该项，不用猜测值继续。

## 前置检查

开始任何板上测试前记录：

1. 板卡丝印/修订版与 V1.0.1 原理图一致（用户已确认）。
2. USB 供电来源、线缆和串口号；当前已知串口为 `COM18`、115200 8N1。
3. 当前固件仍为未知旧固件；记录烧录是否被授权。没有授权时只做串口观察，不进入烧录步骤。
4. 若将来获准烧录，先评估并保存可恢复备份；备份可读性、Flash 加密状态和恢复步骤未确认前，不执行擦除或写入。
5. 构建仅在 ESP-IDF `v5.5.4` 环境明确可用、目标配置确认是 `esp32s3` 后进行。保存 `sdkconfig`、依赖锁文件状态、构建日志和镜像尺寸。

## 测试门槛

| 门槛 | 操作 | 风险控制 / 停止条件 | 验收证据 |
|------|------|--------------------|----------|
| H0-A 串口观察 | 不烧录，记录启动/运行日志、复位原因和供电现象 | 串口乱码、板卡异常发热、USB 反复断连时停止并断电检查 | 原始串口日志、板卡照片/丝印、供电记录 |
| H0-B 诊断镜像构建 | 独立构建最小诊断镜像：启动信息、芯片/内存信息、I²C 总线启动和目标地址探测；不初始化显示、音频、摄像头和 IO 扩展输出 | 仅主机侧构建；构建异常不烧录；不修改分区表或密钥设置 | Git 提交号、`sdkconfig`、依赖锁状态、完整构建日志、镜像大小 |
| H0-C I²C 被动探测 | 在 GPIO1/2 建总线，只探测 7-bit 地址 `0x18`、`0x19`、`0x41`、`0x6A` 和 GT911 常见候选 `0x5D`/`0x14`；只发地址探测，不读写寄存器 | 用户确认烧录后才上板；I²C 初始化或探测超时则立即停止，不自动扫描/改总线频率 | 地址响应表、原始串口日志；未响应不直接判定器件损坏 |
| H0-D PCA9557/LCD 控制链 | 先读取 PCA9557 输入/输出/极性/方向寄存器并记录复位态，再制定仅影响 LCD 所需位的单步测试 | 在查明 LCD_CS、PA_EN、DVP_PWDN 与 EXT-IO 的电平及负载前，不写输出寄存器；禁止整字节覆盖 | 每次寄存器读值、位掩码、实测电平、屏幕状态和断电恢复记录 |
| H0-E LCD 与触摸 | 先验证 ST7796 SPI 基本写屏，再显示色条/坐标网格；触摸需明确 CTP_RST/INT 的 MCU 映射后再初始化 GT911 | 色彩顺序、方向、偏移从图样证据调整；Reset/INT 引脚不明确时跳过触摸 | 色条照片、网格照片、触摸原始坐标与映射参数 |
| H0-F 音频 | 分别确认 codec/ADC 地址、ES8311 输出、ES7210 采样和功放控制 | 首次播放低音量、短时；PA_EN 极性未确认前不使能功放。啸叫、异常电流或温升立即停测 | I²C/初始化日志、播放与采样结果、音量/供电记录、噪声基线 |
| H0-G 摄像头与 IMU | 先验证 QMI8658A ID 与静态采样；摄像头最后单独抓一帧 | 摄像头电源/复位映射未确认前不启用；不并行启用摄像头、人脸识别、音效和动画 | WHO_AM_I、静态数据、单帧尺寸/格式、heap/PSRAM 前后记录 |

## 诊断镜像要求

- 通过独立 board 选择或独立测试入口构建，不把临时代码塞入通用启动路径。
- 默认只输出启动、芯片、Flash/PSRAM 与 I²C 探测结果；不含凭据，不打印 Wi-Fi 密码或 Token。
- 对总线初始化、单地址探测设置有限超时并打印错误码；任何错误都不触发自动引脚重试。
- 不初始化摄像头、屏幕、触摸、功放或 PCA9557 输出，直到对应门槛的控制映射确认。
- 镜像与日志命名包含 Git 提交短哈希和日期；保存当前旧固件恢复方案。

## 回滚与记录

- 烧录前保存原 Flash 读取结果和分区信息；校验备份文件大小/哈希，并确认没有加密导致的不可恢复限制。
- 烧录前记录目标串口、端口占用、目标芯片和完整命令；烧录完成后保存完整串口日志。
- 出现写入失败、启动循环、异常发热或 USB 断连时立即停止，不连续重试；断电后根据已验证的恢复步骤处理。
- 每项结果更新 `hardware_baseline.md` 和 `validation_matrix.md`。图纸推导、软件构建、串口探测、外设实测分别记录，不互相替代。
