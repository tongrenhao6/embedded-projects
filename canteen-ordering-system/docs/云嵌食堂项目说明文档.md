# 云嵌食堂项目说明文档

> 基于 LVGL、Linux 网络编程与阿里云服务器的校园点餐平台  
> 编写日期：2026 年 8 月 3 日

## 1. 项目概述

云嵌食堂是一个面向系统编程、文件 IO、网络编程和 LVGL 学习阶段的校园点餐平台。用户在 6818 开发板的触摸界面中浏览菜品、选择数量、查看购物车并提交订单；开发板通过 TCP 连接部署在阿里云上的 C 语言服务端，由服务端完成菜单读取、购物车维护、总价计算和订单落盘。

项目不引入数据库、账号登录和真实支付等超出当前学习范围的模块，而是将重点放在嵌入式图形界面与云端 Socket 服务的真实联动上。

### 1.1 项目要素

| 项目要素 | 内容 |
|---|---|
| 开发板端 | 6818 Linux 开发板，800 x 480 触摸显示屏 |
| 图形界面 | LVGL 8.2，首页、点餐页、购物车页、下单成功弹窗 |
| 云端服务 | 阿里云 Linux 服务器，TCP 18080 端口 |
| 核心技术 | 文件 IO、单链表、TCP Socket、epoll、多客户端、LVGL |

### 1.2 已实现功能

| 模块 | 实现内容 | 实现位置 |
|---|---|---|
| 菜单管理 | 从文本文件读取 12 道菜品，包含编号、分类、名称与价格。 | `server/data/menu.txt`、`menu.c` |
| 购物车 | 使用单链表保存已选菜品，支持增加、减少、总价计算和释放。 | `cart.c` |
| 多客户端 | 使用 epoll 同时处理最多 16 个客户端，每个连接拥有独立购物车。 | `server_main.c` |
| 订单保存 | 提交订单后以追加方式写入 `orders.txt`，并返回订单号和总价。 | `order_service.c` |
| 点餐界面 | 分类切换、三列菜品卡片、上下滑动、加减按钮、动态合计。 | `ui_order.c` |
| 购物车界面 | 显示已选菜品、数量、小计、总价、返回与结算操作。 | `ui_order.c` |
| 用户反馈 | 网络状态提示、空购物车提示、下单成功弹窗。 | `ui_order.c` |

## 2. 总体设计

### 2.1 系统架构

系统采用开发板 TCP 客户端与阿里云 TCP 服务端的两层结构。开发板通过有线网络接入公网后，连接服务器公网地址 `118.31.185.167:18080`。

```text
6818 开发板触摸屏
        |
        | TCP：MENU / ADD / REMOVE / CART / SUBMIT
        v
阿里云 Linux 服务器（18080）
        |
        +-- menu.txt：菜单文件
        +-- 链表购物车：每个客户端独立保存
        +-- orders.txt：已提交订单记录
```

| 组成 | 运行位置 | 主要职责 |
|---|---|---|
| LVGL 客户端 | 6818 开发板 | 显示界面、读取触摸、发送协议命令、根据服务器响应刷新界面。 |
| TCP 服务端 | 阿里云 Linux 服务器 | 监听连接、管理客户端会话、处理点餐命令、返回结果。 |
| 菜单文件 | 阿里云服务器 | 保存可点菜品，服务端启动和客户端连接时读取。 |
| 订单文件 | 阿里云服务器 | 保存已经提交的订单记录，便于查看历史订单。 |

### 2.2 数据流

```text
用户触摸 + / - / 结算
        ↓
LVGL 事件回调（ui_order.c）
        ↓
TCP 客户端收发（order_client.c）
        ↓  ADD|ID、REMOVE|ID、SUBMIT
阿里云 epoll 服务端（server_main.c）
        ↓
订单业务层（order_service.c）
        ↓
菜单数组 / 链表购物车 / 订单文件
        ↓
OK|CART|总价 或 OK|ORDER|订单号|总价
        ↓
LVGL 更新数量、合计、购物车和下单成功弹窗
```

## 3. 服务端设计与实现

### 3.1 菜单文件与文件 IO

菜单文件采用一行一道菜的简单文本格式，便于直接修改和观察。服务端的 `menu_load()` 使用 `fopen()`、`fgets()` 和 `sscanf()` 逐行读取；`menu_find()` 根据菜品 ID 在菜单数组中查找目标菜品。

```text
# id|category|name|price
10|甜品|泡芙|3.5
```

### 3.2 链表购物车

服务端为每个客户端会话维护一条购物车单链表。链表结点保存菜品信息、数量和 `next` 指针。首次添加某种菜品时通过 `malloc()` 创建结点；再次添加只增加数量；数量减到 0 时将结点从链表中删除并 `free()`。

| 函数 | 作用 | 关键点 |
|---|---|---|
| `cart_init()` | 初始化空购物车 | 将 `head` 设为 `NULL`。 |
| `cart_add()` | 增加菜品 | 先查找已有结点；不存在时创建新结点。 |
| `cart_remove()` | 减少菜品 | 数量大于 1 时减一；否则删除结点。 |
| `cart_total_price()` | 计算总价 | 遍历所有结点，累加价格乘数量。 |
| `cart_clear()` | 清空购物车 | 遍历并释放所有动态申请的结点。 |

### 3.3 epoll 多客户端服务

服务端入口 `server_main.c` 按 `socket()`、`bind()`、`listen()` 的顺序创建 TCP 监听套接字。监听文件描述符和每一个客户端文件描述符都加入 `epoll`；`epoll_wait()` 返回哪个文件描述符可读，服务端就处理哪个事件。

每个客户端连接对应一个 `client_session_t`，其中保存该客户端的 Socket 文件描述符和 `order_service_t`。`order_service_t` 内部拥有独立购物车，因此多个开发板同时点餐时购物车不会相互混合。项目最多允许 16 个并发客户端。

### 3.4 订单业务与持久化

`order_service_handle()` 解析 TCP 请求文本。`MENU` 返回菜单；`ADD` 和 `REMOVE` 修改当前会话购物车；`CART` 返回总价；`SUBMIT` 先将订单追加写入 `orders.txt`，写入成功后才清空链表，避免写文件失败导致已选菜品丢失。

```text
订单号|总价(元)|菜品编号,数量;菜品编号,数量
1|29.00|1,2;4,1
```

## 4. 开发板客户端设计与实现

### 4.1 LVGL 启动与主循环

`main.c` 初始化 LVGL、framebuffer 显示驱动 `fbdev` 和 `evdev` 触摸输入驱动，并设置显示分辨率为 `800 x 480`。`ui_init()` 创建首页和点餐相关界面；`ui_order_connect_server()` 建立首次服务器连接并请求菜单。

主循环每隔约 5 ms 调用 `lv_timer_handler()`。该函数持续处理触摸输入、LVGL 定时器和需要重绘的对象，因此程序不是阻塞等待点击，而是持续轮询和处理界面事件。

```c
while(1) {
    lv_timer_handler();
    usleep(5000);
}
```

### 4.2 TCP 客户端模块

`order_client.c` 将网络操作封装为连接、关闭、加载菜单、添加菜品、删除菜品和提交订单等函数。`send_command()` 通过循环保证一条命令完整发送；`receive_response()` 区分菜单多行响应与普通单行响应，避免一次 `recv()` 假设能收到完整数据。

客户端启动后发送 `MENU`。菜单的名称、分类和价格由服务器返回并覆盖界面本地数据；菜品图片保存在开发板本地，由菜品 ID 与图片资源的固定映射决定，无需通过网络传输图片。

### 4.3 点餐页与购物车页

| 界面模块 | 交互逻辑 |
|---|---|
| 首页 | 由 SquareLine 生成，点击开始按钮进入点餐页。 |
| 点餐页 | 左侧分类按钮；中间菜品卡片三列布局；全部分类支持上下滑动。 |
| 加减按钮 | 发送 `ADD|ID` 或 `REMOVE|ID`；仅在服务器响应成功后更新本地数量。 |
| 底部购物车 | 显示已选份数和服务器返回的总价；点击进入购物车页。 |
| 购物车页 | 按已选菜品连续排列，可滑动查看；显示数量、小计、合计与结算按钮。 |
| 成功弹窗 | 服务器提交成功后显示订单号与实付金额，点击确定关闭。 |

## 5. TCP 通信协议

协议采用 UTF-8 文本格式，一条命令以换行符结束。字段使用竖线分隔，简单直观，便于使用 `nc` 或早期命令行客户端进行调试。

| 请求 | 含义 | 成功响应示例 |
|---|---|---|
| `MENU` | 请求完整菜单 | `ITEM|1|主食|鸡腿饭|12.00 ... OK|MENU` |
| `ADD|ID` | 增加一份指定菜品 | `OK|CART|15.00` |
| `REMOVE|ID` | 减少一份指定菜品 | `OK|CART|12.00` |
| `CART` | 查询当前购物车总价 | `OK|CART|12.00` |
| `SUBMIT` | 提交当前订单 | `OK|ORDER|1|12.00` |

> 一致性策略：加减按钮不会在发送命令前先修改界面数据。只有解析到服务端 `OK|CART` 响应后，客户端才改变数量和总价，从而避免网络失败时界面与服务器状态不一致。

## 7. 部署与运行方法

### 7.1 阿里云服务器

在阿里云 Linux 服务器中进入 `server` 目录，使用 Makefile 编译并以前台或后台方式启动。安全组和服务器防火墙需要放行 TCP `18080` 端口。

```bash
cd ~/cloud_embedded_canteen/server
make server
nohup ./build/order_server data/menu.txt data/orders.txt > server.log 2>&1 &
echo $! > server.pid
```

可使用以下命令确认服务端状态：

```bash
ss -lntp | grep 18080
tail -f data/orders.txt
```

### 7.2 6818 开发板

在交叉编译环境中进入 `lv_port_linux-v8.2` 目录执行 `make`，生成的程序下载到开发板后运行。开发板需配置可访问公网的默认路由，并能够连接阿里云公网地址。

```bash
cd lv_port_linux-v8.2
make
# 将 build/bin/demo 下载到开发板后运行
```

## 9. 项目特点与可扩展方向

项目以较小的功能范围串联了嵌入式界面、Linux 文件 IO、动态内存、TCP 网络通信和 epoll 多路复用。服务端按模块拆分为菜单、购物车、订单业务和网络入口，客户端将网络收发与界面逻辑分离，便于理解和后续维护。

| 当前边界 | 后续可扩展方向 |
|---|---|
| 菜单在客户端建立连接时读取 | 增加菜单更新命令或后台管理页面。 |
| 购物车只在 TCP 会话存活期间保存 | 使用文件或数据库保存用户购物车。 |
| 没有用户身份与真实支付 | 增加桌号、用户信息、支付状态和订单查询。 |
| 订单记录为文本文件 | 增加订单管理、统计报表和数据库存储。 |

## 10. 总结

云嵌食堂完成了从 6818 开发板触摸界面到阿里云服务端订单记录的完整链路。用户的每一次点餐操作都会通过 TCP 协议到达服务端，服务端使用独立链表购物车处理当前客户端的数据，并将最终订单写入文件；开发板根据服务端响应实时更新界面。

该项目验证了嵌入式端与云端服务协同工作的基本方法，也为后续增加用户系统、订单管理和数据持久化打下了清晰的模块化基础。
