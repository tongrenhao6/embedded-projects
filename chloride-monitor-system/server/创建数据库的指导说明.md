# 数据库交接说明

## 推荐做法

把这份项目交给学弟时，优先使用：

- 项目源码
- `.env.example`
- `sql/init.sql`
- 这份数据库交接说明

不建议直接导出你当前整库作为默认方案，原因：

- 当前库里大多是测试数据，价值不高
- 导出的整库会把历史脏数据、测试命令、错误记录一起带过去
- 学弟以后换电脑、重装数据库时，还是得重新学一遍怎么初始化
- 用初始化脚本更容易保证“环境可重复搭建”

## 什么时候才需要导出整库

只有在下面这些情况，才建议额外导出数据库：

- 你们要保留当前测试数据做演示
- 某些数据不是脚本生成的，而是你手工录进去的关键配置
- 学弟需要复现你当前数据库里的命令记录、样本数据、上传状态

如果只是为了让项目正常启动和联调，`sql/init.sql` 就够了。

## 学弟拿到项目后需要做什么

### 1. 准备环境

需要先安装：

- Node.js
- MySQL
- MQTT Broker（如果需要和设备联调）

### 2. 安装依赖

在项目根目录执行：

```powershell
npm install
```

### 3. 配置 `.env`

可以复制 `.env.example` 为 `.env`，再按自己的环境修改。

最少要确认这些配置：

```env
PORT=3000
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你的数据库密码
DB_NAME=water_monitor
MQTT_URL=mqtt://你的MQTT地址:1883
MQTT_USERNAME=root
MQTT_PASSWORD=你的MQTT密码
MQTT_BASE_TOPIC=phwater/v1
MQTT_CLIENT_ID=ph_water_server
```

## 创建数据库

### 方式一：推荐，直接执行初始化脚本

在项目根目录执行：

```powershell
mysql -u root -p < sql/init.sql
```

作用：

- 创建数据库 `water_monitor`
- 创建项目所需全部表
- 插入默认设备
- 插入默认传感器
- 插入默认用户

### 方式二：已有库，补升级脚本

如果数据库已经建过，但缺少某些表：

补用户表：

```powershell
mysql -u root -p water_monitor < sql/upgrade-users.sql
```

补上传状态表：

```powershell
mysql -u root -p water_monitor < sql/upgrade-upload-status.sql
```

## 初始化后数据库里会有什么

默认会创建这些核心表：

- `devices`
- `sensors`
- `samples`
- `sample_values`
- `commands`
- `upload_logs`
- `device_upload_status`
- `users`

默认还会写入：

### 默认设备

```text
device_sn: ph_terminal_001
name: pH water monitor 001
```

### 默认传感器

```text
sensor_type: ph
sensor_addr: 3
name: pH RS485 sensor
```

### 默认网页账号

```text
管理员：admin / admin123
普通用户：user / user123
```

如果你们后面改过密码，这里要单独告诉学弟，不然他会按默认密码登录。

## 启动项目

数据库建好、`.env` 配好后，在项目根目录执行：

```powershell
npm start
```

成功后浏览器打开：

```text
http://127.0.0.1:3000
```

未登录时会自动跳转到：

```text
http://127.0.0.1:3000/login.html
```

## 如何验证数据库初始化成功

### 方法一：看 MySQL 里是否有库和表

进入 MySQL 后执行：

```sql
SHOW DATABASES;
USE water_monitor;
SHOW TABLES;
SELECT * FROM devices;
SELECT username, role, enabled FROM users;
```

### 方法二：直接启动项目

如果项目能正常启动，登录页能打开，登录后能看到页面，就说明数据库结构基本没问题。

## 如果你一定要给学弟一份“完全一样”的数据库

那就不是“初始化说明”了，而是“整库快照”。

可以导出：

```powershell
mysqldump -u root -p --databases water_monitor > water_monitor_dump.sql
```

学弟导入：

```powershell
mysql -u root -p < water_monitor_dump.sql
```

这种方式的特点：

- 优点：数据、记录、命令历史都一模一样
- 缺点：会把测试数据和历史脏数据一起交过去

## 最终建议

交付时建议你发给学弟这四样：

1. 项目源码
2. `.env.example`
3. `sql/init.sql`
4. 这份 `DATABASE_SETUP_GUIDE.md`

如果你们需要保留当前测试记录，再额外补一份数据库导出文件，而不是只给导出文件。
